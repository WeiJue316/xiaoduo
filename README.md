# xiaoduo · 自动回复质量评估流水线

评估"客服自动回复"功能回复质量的自动化流水线，把业务方一句模糊需求
（"回复要**准确**、**有用**、**语气好**、**不能瞎编**"）落成一套**可运行、可解释、复用**的
评分方案，用于回答业务决策：**这套自动回复到底能不能扩大覆盖范围**。

---

## 1. 指标定义及理由

从人工标注（`attachments/task3_human_ref.json`，20 条 human reference）中我们发现最强的
判别维度并不是"回复写得多全"，而是——**好回复主动帮用户解决，而非把责任/操作/判断抛回给用户**。
据此定义三个指标，均按 **0–5 半整数** 打分：

| 指标 | 定义 | 为什么这么量化 |
|---|---|---|
| **主动协助度**（核心） | 是否真正解决用户问题、主动查证/代办，而非把操作抛回用户；"正确但没用"的回复在此应得低分 | 人工标注的核心共识；最贴近业务意图（用户要"帮我办"，不是"教我自己办"） |
| **准确性 / 不瞎编** | 是否事实正确、命中问题核心、无臆造信息、不答非所问 | 业务方明确要求；直接关系到信任与合规 |
| **语气 / 同理心** | 用户流露情绪（焦急/生气/害怕/抱怨）时安抚是否到位 | 客服体验的软指标，直接影响流失与投诉 |

**指标优先级**：主动协助度 > 准确性 > 语气。主动协助度最贴近业务增值，但三者不互相替代，
故报告**分维度呈现 + 等权算术平均得整体分**，**不设额外权重**（避免引入主观加权，少一层争议）。

> 评分锚点见 `src/metrics.py::RUBRICS`，每个分数档给出一条可辩护的行为描述。

## 2. 评估方法

```
attachments/ 20 条自动回复
      │ 逐条
      ▼
LLM judge（DeepSeek-V4-Flash，经火山 Agentplan）
      │ 输出 {usefulness, accuracy, tone, reason}
      ▼
scorer：聚合三指标等权均分，seed 固定，结果落盘 outputs/scored_cases.json（可追溯）
      ▼
一致性验证：vs 人工三档 ground truth（命中率 + Spearman）
      ▼
report.md + report.html（分布 / 全表 / 最差3条详解 / 局限性）
```

- **主动协助度阈值映射到人工三档**（主动解决 / 正确但没帮上 / 差），用于事后验证方法是否贴合人工判断。
  验证结果会**如实写入报告**（当前 mock 演示：命中率 90%，Spearman 0.795），不隐瞒偏差。
- **`--real` / `--mock` 双引擎**：`--real` 调真实 DeepSeek（seed 固定压随机）；`--mock` 为确定性
  参考实现，无 key 也能全链路演示。真实与 mock 返回结构完全对齐。
- **可追溯**：每次运行写入 run meta（引擎类型、模型、seed、时间戳），报告标注数据来源。

## 3. 运行方式

```bash
# （可选）配置真实引擎，复制模板填入 endpoint/api_key，真实 key 不符入 git
cp config/config.example.json config/config.json   # 然后编辑填写

# mock 全链路演示（无需 key，确定性可复现）
python scripts/evaluate.py --mock

# 真实 DeepSeek 评估
python scripts/evaluate.py --real --config config/config.json

# 跑测试（含 human_ref 一致性验证断言）
python -m pytest tests/ -q
```

运行产物生成到 `outputs/`：`scored_cases.json`、`validation.json`、`report.md`、`report.html`（可浏览器打开）。

## 4. 当前结果摘要（mock 演示运行）

- **整体均分 3.4 / 5**，结论：处于中等水平，暂不建议激进扩大覆盖。
- 核心短板是**主动协助度**（均值 2.9）——大量回复"正确但把操作抛回给用户"。
- 最差 3 条：**case_13**（敏感肌被打回"自己看详情页"）、**case_08**（"正确但没用"）、**case_20**（用户已说搞不懂却重复流程）。
  均已对照人工标注逐条详解，见 `outputs/report.md`。

> 当前为 **mock 演示结果**，用于验证方法与结构；待填入真实 Agentplan 配置后用 `--real` 复跑替换。

## 5. 局限性

1. **指标盲区**：把"确实只能给信息、不该代办"的回复判低；"正确但没帮上"↔"差"档位边界主观。
2. **judge 偏差**：LLM 倾向打偏高/往中间收缩；DeepSeek 中文稳定性需抽查。→ 多模型交叉 + 抽样人工复核（kappa）。
3. **样本与场景**：仅 20 条、单客服场景、无多轮上下文，不可回测跨版本。→ 扩样本分层 + 真实多轮会话。
4. **标注噪声**：human_ref 为单人主观、无数值，无法真正校准。→ 双注释者 + 升级为三档+各指标打分。

每类局限性在报告中附"具体影响 → 踩雷 case → 改进"。

| ground truth 三档编码 | **人工读取** `task3_human_ref.json` 的注释后编码，AI 不参与推理 |
| 评分执行 | mock 演示=确定性参考实现；真实评分由 **DeepSeek-V4-Flash** 完成（待配置后运行） |
| 报告生成 | AI 从真实运行结果自动生成，数字可追溯到 `outputs/`，不凭空补数 |

> 生成的评分/统计均可追溯到实际运行产物，AI 未编造任何数值。
